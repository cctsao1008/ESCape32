# AM13E23019 port

This directory is the AM13E23019 platform bring-up area for the `am13e-port`
branch.

## Stage A — relocatable application baseline

The first target is deliberately small:

- TI AM13E230x SDK 26.01.00.03.STS
- SysConfig 1.28.0.4712
- Arm GNU Toolchain 15.2.rel1
- No-RTOS
- TI DriverLib / SDK startup baseline
- no ESCape32 motor-control behavior yet

The flash contract under validation is:

```text
0x00000000..0x00003FFF  Bootloader      16 KiB
0x00004000..0x00004FFF  FW1 parameters    4 KiB
0x00005000..0x00005FFF  FW2 parameters    4 KiB
0x00006000..0x0007FFFF  Application      488 KiB
```

The application now uses the repo-owned `linker_app.ld`, derived from TI SDK
26.01.00.03's GCC layout. It preserves TI's RAM and `.TI.ramfunc` conventions
while restricting application Flash ownership to
`0x00006000..0x0007FFFF`.

The target reuses the SysConfig C/H output generated by the pinned TI SDK
`ex_empty_lp` smoke build. This keeps Stage A comparable with TI's known-good
startup/clock/flash baseline without copying generated files into the repo.

CMake's deferred execution does not allow `add_subdirectory()`. The wrapper
therefore schedules a deferred `include()` of this target definition after the
TI SDK top-level directory has created its config/source targets.

The linker is now the build-time enforcement point for the E62 application
partition. Runtime Flash-update ownership is enforced separately by the common
bootloader and FW1 parameter-storage implementation.

## Build

From the ESCape32 repository root:

```bash
./tools/am13e/build-am13e-bringup.sh
```

Expected ELF invariants:

```text
.intvecs     0x00006000
.text        >= 0x00006100
.vtable      absent for interrupt-free Stage A, or 0x20000000 if linked
.TI.ramfunc  0x00C18000
ABI          hard-float
```

The TI RAM vector table is supplied by the interrupt relocation implementation.
Because Stage A does not register or enable interrupts, GCC/linker section
garbage collection can legitimately omit that archive member and therefore the
`.vtable` section. Once an interrupt path is introduced, the build validation
will require any linked `.vtable` to remain at TI's baseline address
`0x20000000`.


## Boot Porting — common boot/application launch contract

The AM13E bootloader has a separate target under
`boot/mcu/AM13E23019`.

The current implementation establishes the architecture-fixed behavior:

- boot image owns `0x00000000..0x00003FFF`;
- application starts at `0x00006000`;
- minimum application-vector sanity check;
- direct Cortex-M33 VTOR/MSP/reset-entry handoff;
- no FW1/FW2-specific launch behavior.

Build:

```bash
./tools/am13e/build-am13e-boot.sh
```

The shared `e62_flash_layout.h` is the code-level representation of the E62
v1.4 Flash contract.
